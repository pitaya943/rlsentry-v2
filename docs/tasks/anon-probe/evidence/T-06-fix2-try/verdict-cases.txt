## d3: verdict D3, its reproduction: an INSTEAD rule sends the PATCH to other.inbox
```sql
create schema other;
create table other.inbox (id bigint, note text);
grant usage on schema other to anon;
grant all on other.inbox to anon;
create table inbox (id bigint generated always as identity primary key, note text);
alter table inbox enable row level security;
create policy s on inbox for select to anon using (true);
create policy u on inbox for update to anon using (session_user = 'authenticator');
create rule no as on update to inbox do instead update other.inbox set note = new.note where false returning other.inbox.*;
```
$ rlsentry attack --migrations d3
rlsentry: could not build or attack the copy: inbox: UPDATE got no answer from row-level security, so it is neither exposed nor protected (PATCH by primary key: HTTP 204)
[exit 2]
