# T-04: Value search and the complete lab

Status: open
Risk: medium (inside the attacker; it reads catalogue data through the sandbox)
Scenarios: S-5, S-9
Depends on: T-02, T-03
Areas: `rlsentry/attacker.py`, `rlsentry/sandbox.py` (read-only catalogue query), lab

## What
Design §4 value search: when insert was rejected by a policy, try up to 50 candidate rows
from seeded values, constants in that table's policy expressions and CHECK constraints
(`pg_policies`, `pg_constraint`, read by the sandbox, not the attacker), enum labels, and
`null`. The report names the source that succeeded, or `protected (N rows tried)`. Lab gains
`lab_value_policy` (`with check (status = 'pending')`). `expected.json` covers all eight
design §5 tables.

## Check (fails today: value-policy table is judged protected)
- `lab_value_policy`: INSERT EXPOSED, evidence row has `status = 'pending'`, source named.
- A table whose policy accepts nothing anon can produce (`auth.uid() = user_id`):
  `protected (N rows tried)` with N ≤ 50.
- The lab report has at least one table for each verdict kind listed in S-9 and matches
  `expected.json` exactly.

## Added after T-02's verification (PR #4 verdict, Findings F1-F4)
These are all "a verdict that is not backed by an attack" or "an exit code that lies", the
same class T-01's verification found. Fix the class in `attacker.py` / `cli.py`:
- F1: a 5xx on any operation is exit 2. Add a test that fails when that branch is removed
  (change `>= 500` to `>= 600`: the suite currently passes).
- F2: any unexpected exception after the sandbox is built tears down and exits 2, never 1
  (S-10 reserves 1 for "exposed"). Check: make `Sandbox.restore` raise on its 2nd call; exit 2.
- F3: an operation that was not attempted (e.g. no settable column) must not read
  `protected`. It stops the run with exit 2, naming the table and operation, as T-03 does
  for unseeded tables.
- F4: UPDATE picks a column whose new value cannot hit a unique constraint, or retries
  another column on 409. Check: the verdict's reproduction (`email text not null unique` first,
  update open to anon) gives `UPDATE: EXPOSED`.
Risk stays medium unless the diff touches the guard or teardown.
