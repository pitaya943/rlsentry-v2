# T-01: Sandbox, guard, read attack, report — first runnable slice

Status: open
Risk: high (the live-target guard and teardown are the brief's Critical areas)
Scenarios: S-1, S-3, S-7, S-8, S-10
Depends on: nothing
Areas: new package `rlsentry/`, `pyproject.toml`, `tests/`, `.shilaycow/config.yml` (`test_command`), `.claude/skills/try-rlsentry/`

## What
Follow `design.md` §1, §2, §3 (steps 1, 2, 4, 6 and a minimal step 5), §4 read only, §6.

- Python package `rlsentry`, installable with `pip install -e .`, with a console script `rlsentry`.
  Keep dependencies few. Stdlib is fine for HTTP and HS256 JWT; a Postgres driver is
  acceptable.
- `Sandbox` with the **local backend** (design §8 D-1): `initdb`/`pg_ctl` from PATH or
  `/usr/lib/postgresql/<v>/bin`, `postgrest` from PATH. When running as root, run Postgres as an
  unprivileged user (e.g. `postgres`), with the data dir in a temp dir that user owns. Random
  free ports on 127.0.0.1. Supabase roles plus default grants on `public` (design §3 step 2).
  Migrations applied in filename order. Minimal seed: 5 rows per table for simple column
  types. Per-run nonce.
- `AnonChannel` constructed only by a running `Sandbox` (design §2). `--target <url>` parsed
  and refused with exit 2 and no network use.
- Read attack through PostgREST with an anon JWT. Verdict and evidence per design §4.
- Report: text and `--json` (design §6 types), exit codes 0/1/2.
- Teardown in `finally`, SIGINT/SIGTERM, plus the startup sweep of stale labelled
  resources (design §3). For the local backend the "label" is a marker file/dir naming the run
  id and pids, under a fixed rlsentry state dir.
- `rlsentry attack --lab` and `--migrations <dir>`. The lab starts with `lab_rls_off`,
  `lab_using_true` and `lab_no_policy` (read only for now), with `lab/expected.json` holding only
  what T-01 can judge (READ).
- Set `test_command: "python3 -m pytest -q"` in `.shilaycow/config.yml`.
- End by creating the project skill `try-rlsentry` with `shilaycow-try-it`.
