# T-05: Docker backend

Status: done
Risk: high (process and container lifetime on the user's machine: teardown is a Critical area)
Scenarios: D-1 (a); S-8 for this backend
Depends on: T-01
Areas: `rlsentry/backends/docker.py`, backend selection in the CLI

## What
Design §8 D-1: a `docker` backend behind the same `Backend` interface, with pinned images
`postgres:16` and `postgrest/postgrest:v12.2.3`. Containers labelled `rlsentry.run=<id>`, `--rm`,
ports bound to 127.0.0.1 only, swept at startup. `--backend auto|docker|local`; `auto` tries
docker and falls back to local when no daemon answers or an image cannot be pulled.

## Check
- Unit (fails today): the command lines built for `docker run` bind only `127.0.0.1`, carry the
  label, and pin both images by tag; `auto` falls back to local when the daemon is absent
  (simulate the absence).
- Integration when a Docker daemon answers: lab run on `--backend docker` matches
  `expected.json`, and no labelled container remains afterwards. In this cloud environment
  there is no daemon and Docker Hub rate-limits anonymous pulls. If that integration cannot
  run, say so in Ready; it is reported as a gap, not passed.
