# T-07: Only an answer the copy confirms decides a verdict (PR #10 fix round 1)

Status: done
Risk: high (decides every READ verdict; the channel is the only way rlsentry reaches the copy, a
Critical area: "nothing outside the throwaway copy is ever attacked")
Scenarios: S-1, S-2, S-3, S-7 (READ verdicts; the attacker only ever reaches the copy)
Depends on: T-06 (its log machinery: `_Log`, `Inspector._said`)
Areas: `rlsentry/channel.py`, `rlsentry/attacker.py` (`read`, `_send`), `rlsentry/sandbox.py`
(`Inspector`, `_wait_http`), `docs/spec/`, `reports/final.md`

## Why
The FAIL verdict on PR #10 at 4c7fccb
(https://github.com/pitaya943/rlsentry-v2/pull/10#issuecomment-7143781168):
- **D1.** The channel follows redirects (urllib's default `HTTPRedirectHandler`). Migration
  code can set `response.status` / `response.headers` through PostgREST, so the anon request,
  JWT included, goes to any host, and READ is decided from whatever answers there: a fabricated
  `READ: EXPOSED` (exit 1), or a false `READ: protected` with exit 0.
- **D2.** READ `EXPOSED` is taken from the body's length; the spec and the report say the
  superuser confirms it. A GET answered 42501 is `protected` from the body alone (trail row 177).

The class is the one of T-04 and T-06: a verdict that trusts an HTTP answer the copy did not
confirm. Fix the class: no HTTP client of rlsentry follows a redirect, and READ meets the bar
writes meet.

## What
- The channel never follows a redirect; a 3xx answer to any attacking request stops the run
  (exit 2), naming the table and operation. Every other HTTP client in rlsentry
  (`_wait_http`) uses the same no-redirect, no-proxy opener.
- READ `EXPOSED` only when every row anon received is a row the copy's superuser sees in that
  table (as a multiset); otherwise exit 2.
- READ `protected` only on PostgreSQL's own account of that very request (T-06's `_Log`,
  correlated by `X-Rlsentry-Request`): `aclcheck_error` for this table at the top level (a GET
  answered 42501), or auto_explain's plan of PostgREST's read showing no row reached it (a GET
  answered `[]`). Anything else is exit 2.
- Keep `rlsentry/lab/expected.json` exactly, `supabase_app`, every existing test, both backends,
  S-7 and S-8.

## Check (fails today at 4c7fccb)
- The verdict's two reproductions (fabricated EXPOSED, false protected through a redirect):
  exit 2, nothing reaches the listener.
- A 302 on POST, PATCH and DELETE: exit 2, nothing reaches the listener.
- `_wait_http` follows no redirect.
- An answer that is not the copy's as the copy gave it (fabricated rows, a real row twice, `[]`
  or 42501 in place of the copy's rows, `[]` without asking the copy): exit 2.
- A policy raising 42501 with the grant's own message on GET: exit 2; a revoked grant:
  protected.
- Without the server's jsonlog, READ is no answer either.
- Mutants on worktrees of HEAD: redirects followed again; READ EXPOSED without the superuser
  check; READ protected without the log; each guard on the new READ path.
